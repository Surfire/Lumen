# 如何判断 Lumen 是否真的比 Spotlight 和 Tinycast 快

**以下数字是建议的发布门槛，不是成绩。** 只保存来自同一次实测的结果，不把旧版 Luminator 的成绩记在 Lumen 名下。把“快”写成可复验的句子：在哪台机器、多少数据、哪类查询、结果是否正确、相同口径的 p95 改善多少，以及为此多用了多少内存、电量和磁盘。

## 固定数据与实验顺序

1. 三个互补样本：①固定种子的 1 万和 100 万条合成路径（含汉字、拼音、多音词、数值编号、重复名、重音、深目录）；②实际落盘的合成文件树（建库/变更时延）；③本地授权内容样本（全文和语义）。合成内存查询不可用于推断全盘扫描。评测集生成、构建及扫描时间分别报告；不要提交用户私有测试库。
2. 用已知期望清单校验结果。涉及同义改写的语义样本，至少保留 50 条盲测问题，其中至少 30 条中文；另加 20 条库中没有答案的问题。开发集/盲测集分开，包含跨语言或无词面重叠样例。分别报告 Hit@5、MRR@10、无答案误报，不能拿输出了非空列表当通过。
3. 在本机记录 CPU/芯片、内存、OS/编译器、release 配置与提交、后台负载、电源、索引覆盖及语料标识。比较前两侧索引都就绪，且都能访问样本。若没有权限让竞品完整覆盖，报“不可比”，而不是拿对方返回空结果的耗时当基线。测试默认只用临时合成目录；不要接管用户会话、不提高系统权限。
4. 每个类别至少 50 个不同查询；交错随机执行、至少 20 次/查询。分别报告 p50/p95/p99、样本数、超时/漏召回数。首次、热查询、缓存命中、连续键入单独列；进程冷启动不等于冷磁盘。若包含后台索引，披露持续写入负载；别只挑最有利的两条查询。

## 必须同层计时

| 测什么 | Lumen 起止点 | 对手与结论边界 |
|---|---|---|
| 纯名称/拼音引擎 | 查询进入热索引 → 有序 Top-K 及路径就绪 | 仅引擎；不与打开 GUI 比 |
| 命令行 | 新客户端进程启动 → 收到完整输出 | 可和同查询语义的本机 mdfind 比；包括进程启动和打开索引；不能代表 Spotlight UI |
| 启动器首屏 | 最后有效输入 → 第一帧可操作且含正确结果；含防抖、跨进程、渲染 | 分别在 Spotlight 与未改版 Tinycast 的相应搜索入口测；若切换模式有成本另报。未经允许不碰用户正在使用的桌面 |
| 云盘 | 文件名可见/不可见、是否发起内容取回 | 一次仅列名称与一次开启全文都要测；普通文件假扮占位符只算策略单测，不能代替真实提供商验证 |
| 首次建库与更新 | 开始枚举 → 已持久化且可查；创建/改名/删除 → 结果可见且旧名消失 | 分离元数据、全文、向量的各自进度；批量更改中仍需测前台查询延迟 |

测真实 UI 时用用户可见的同一查询文本、相同返回条数、相当的输入等待与渲染条件；不要把 Lumen 内部计时和竞品窗口级耗时摆在同一“倍数”栏。竞品不能回报同一搜索语义（例如不支持拼音）可记“能力差异”，不算无限倍加速。

## 建议发布门槛

| 场景 | 建议门槛 | 失败说明 |
|---|---|---|
| 百万条热名称，普通查询 | p95 ≤ 20 ms；批量更新时 p95 ≤ 40 ms | 单字/高扇出另列；不能为了速度偷偷截断结果 |
| 快捷键启动器，首批准确文件 | 热态 p95 ≤ 100 ms | 没有可操作首帧数据时只报 CLI 或引擎成绩 |
| 本地变更可见 | 单项增删改名 p95 ≤ 1 s | 声明事件机制或重扫粒度；如仅手动重扫，不能报告实时刷新通过 |
| 全文 / 语义 | 10 万实际片段：热全文 p95 ≤ 100 ms；热语义含嵌入与排序 p95 ≤ 500 ms；质量 Hit@5 ≥ 90%，无答案误报 ≤ 10% | 披露模型、语言、维度、量化、样本；模型不可用、不返回结果不算成功 |
| 系统影响 | 待机 60 s 平均 CPU < 1 个核的 1%；百万名称常驻进程组物理内存目标 ≤ 200 MiB；首扫峰值单列 | 不把内存映射大小充作实际物理内存；语义模型与辅助进程另计 |
| 云盘与权限 | 全流程无由索引发起的内容下载；越界文件不被搜出，正常目录不因单项失败而隐身 | 对真实 OneDrive/iCloud 分别验，不能用假文件替全部网盘背书 |

**对外比较的门槛：** 口径、正确率和 Top-K 相当的同机盲测中，对同一对手、同一任务，预先定义的“明显更快”为 p95 至少快 2 倍，且没有明显漏召回或交互退化。逐对手/逐任务给数据；即使名称查询达标，也不能称全盘、全文、语义或“所有场景”都超过对方。此处不承诺任一对手一定较慢。
